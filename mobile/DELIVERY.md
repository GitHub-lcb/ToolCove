# 铁路大亨 · 手机悬浮面板 — 交付说明

一句话：**安卓手机上，把「下一站是什么」压在其他应用（游戏）之上显示，可以直接在面板上录入站点**，
并且能把进度导出 / 导入，和电脑上的 ToolCove 桌面版互通。

---

## 一、拿到手的东西在哪

| 文件 | 是什么 | 怎么用 |
|------|--------|--------|
| `mobile/android/out/railpanel-release.apk` | **手机应用**（688 KB） | 拷到手机上点开安装 |
| `mobile/rail-hud/dist/index.html` | 单文件网页版（80 KB，无外部依赖） | 丢了也行；用手机浏览器直接打开就能当纯网页版用 |
| `mobile/android/README.md` | 工程说明（给改代码的人） | 开发时看 |

APK 是 **debug 签名**的，侧载（自己装）完全够用，不用任何账号。

## 二、装上之后怎么用（按顺序）

1. **拷 APK 到手机**：微信/QQ 传文件、数据线、网盘都行。点开安装时系统会问
   「允许安装未知来源应用」——允许即可。
   也可以走命令行：`adb install -r mobile\android\out\railpanel-release.apk`

2. **打开应用 → 点「去授权（显示在其他应用上层）」**
   这是悬浮窗的必需权限（`SYSTEM_ALERT_WINDOW`），系统会跳到设置页，
   打开那个开关，然后返回应用。应用会自动识别到已授权。

3. **点「开启悬浮面板」**
   通知栏会出现一条常驻通知（前台服务的标志，正常的）。现在切到游戏，面板就浮在画面上了。

4. **用面板**：
   - 按住面板**顶部那条窄条拖动**位置；
   - **点一下窄条**在「展开」和「收成一条」之间切换（收成一条时只剩结论，遮挡最小）；
   - 面板上是「结论 + 类型三选一 + 提示四选一」，记完一站会自动跳到下一站。

5. **要录入/查看全部 16 站、导出导入** → 回应用点「打开完整页面」。

## 三、和电脑互通进度

两端的进度**默认是各自独立的**（手机存在本机，电脑存在 ToolCove 的数据目录），
所以给了导出 / 导入：

- **电脑 → 手机**：桌面版 ToolCove 的铁路大亨工具里点「导出」，把 JSON 拷到手机
  （微信发给自己、或者随便什么方式）→ 手机「完整页面 → 导入」→ 粘贴 JSON → 「导入并覆盖」。
- **手机 → 电脑**：反过来，手机「导出」→ 复制 JSON → 桌面版「导入」。

导出的 JSON 是自描述的（带 `kind` 和导出时间），导入时会校验：不是铁路大亨的进度会被明确拒绝，
不会把别的工具的数据硬塞进这 16 个格子里。

## 四、必读：各家系统会杀后台

悬浮窗这类应用在国内 ROM 上**默认会被省电策略干掉**，表现为「面板过一会儿自己消失了」。
如果遇到，按你手机的品牌做一次设置（应用里「省电与后台」那段也写了同一份清单）：

| 品牌 | 要开的东西 |
|------|-----------|
| 小米 / 红米 | 设置 → 应用设置 → 应用管理 → 权限管理 → **自启动**；省电与电池 → 应用智能省电 → **无限制** |
| 华为 / 荣耀 | 设置 → **应用启动管理** → 关掉「自动管理」→ 允许自启动 / 关联启动 / 后台活动 |
| OPPO / realme | 应用管理 → **耗电管理** → 允许完全后台行为 / 允许自启动 |
| vivo / iQOO | 设置 → 电池 → **后台耗电管理** → 允许后台高耗电；权限管理里单独开「**悬浮窗**」 |
| 三星 | 设置 → 电池 → 后台使用限制 → 加入**从不休眠的应用** |

> 通知权限被拒绝**不影响**面板工作，只是那条常驻通知不进通知栏；
> 系统的「正在运行的应用」里仍然看得到它，也仍然能从那里停掉。

## 五、可能遇到的问题（先看这里）

**面板出来了，但被面板盖住的那块游戏点不动**
这是最可能遇到的情况，原因是游戏自己开了防遮挡（`setFilterTouchesWhenObscured`），
被遮挡区域的触摸会被游戏主动丢弃。三个办法：
① 把面板拖到不挡操作区的位置；② 点窄条收成一条；③ 只在需要看结论时开面板。

**面板显示「记录有矛盾」**
说明录入的某一条和其余记录冲突（最常见：把「X 最多」记成了「只出现 1 次」，
或者漏记了某站的提示）。面板会直接**指出是哪一条**（例如「第 3 站的提示、第 4 站的类型」），
点「全部记录」在覆盖层里改那一格即可，改完立即重算。

**站号对不上**
工具里的「第 N 站」= 游戏里的「第 N 站」，**始发站不编号**（它也不是三类店铺之一，没有类型）。
始发站同样要记它那条「未来 3 站」提示（覆盖第 1~3 站）。

## 六、这个版本**没有**做的事（说明白，免得以为是坏了）

- **不能打字**：面板是刻意不抢输入焦点的（否则你在面板外点游戏会没反应），
  代价是软键盘弹不出来。所以录入、导出、导入都在「完整页面」里做。
- **iOS 没有**：iOS 系统不允许任何应用浮在其他应用之上，这条路在 iPhone 上不存在。
  手机上要看结论只能用安卓。
- **不是自动同步**：跨设备靠导出 / 导入 JSON，不是实时同步。
- **没有上架应用商店**：侧载 APK。也因此不需要账号、不联网（面板本身全程本地计算）。

## 七、想自己改 / 重新构建

```bash
npm run build:mobile    # 只重新生成网页那一半（80 KB 单文件）
npm run build:apk       # 重新打 APK（首次会下载工具链，约 500 MB，之后可 --offline）
```

代码结构、关键设计取舍（为什么是两个 WebView、为什么初始状态由原生注入、
为什么构建脚本用 Groovy）都写在 `mobile/android/README.md` 里，
`mobile/rail-hud/*.test.js` 有 72 个单测守着核心逻辑与文案同步。

## 八、还没验证的部分（诚实说明）

APK 在本机构建并**通过静态校验**（签名有效、`foregroundServiceType=specialUse` 正确、
图标与内嵌页面都在包里、产物脚本语法合法），但**这台机器上没有连接安卓设备**，
所以以下必须在真机上确认：

1. 悬浮窗能正常显示、可拖动、可收起；
2. 目标游戏是否开了防遮挡（见第五节第一条）；
3. 面板 / 全屏页之间的状态同步（应该实时，用的是原生广播）；
4. 各家 ROM 的保活设置是否按预期生效。
