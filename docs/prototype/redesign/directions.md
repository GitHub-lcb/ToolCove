# 六个候选与三张完整版

先看 `spec.md`（说什么）和 `brand-spec.md`（资产）。下面是六个候选的方向卡，最后标出挑了哪三张做完整版、为什么。

- App 分区 12 种 → 7 % 12 + 1 = **第 8 号：键盘优先命令面板（Raycast 式）**
- 东亚分区 12 种 → 7 % 12 + 1 = **第 8 号：杉浦康平信息曼荼罗**

## 1 · 深泽直人 · Quiet（安静派）　【备选】

- **逻辑与来源**：最佳设计师。深泽直人的「无意识设计」：不靠标签解释，靠物体的形状和位置让人自动会用；原型是 MUJI 的壁挂 CD 机、±0 的家电。这里问的是：一个每天开十几次的工具，能不能做到「没有界面」。
- **借的是什么**：① 一屏只有一个主动作，其余退成灰度；② 控件与内容同材质，不用投影分层，用留白和 1px 线；③ 状态变化靠位置（东西挪了 2px）而不是颜色闪。
- **主角素材**：产物本身——待写入的 JSON 文档，居中如一张纸；Agent 的步骤退到左侧页边，像铅笔批注。
- **骨架**：单栏纸面 + 左侧页边批注栏 + 底部单行输入条。没有工具栏、没有右栏。
- **胆量花在哪**：整屏几乎没有一个「按钮」的造型；允许写入是一个贴着文档右下角的签名式控件。
- **form 来自内容的哪里**：文档是这个产品真正的产出物，所以让文档占据视觉中心，而不是让运行日志占据。

## 2 · Bret Victor · Pipeline（直接操作）　【完整版 B】

- **逻辑与来源**：最佳设计师。Bret Victor 的「可被看见的思考」（`Learnable Programming`、`Inventing on Principle`）：把机器内部的每一步变成屏幕上可以指、可以展开的实体，而不是一行日志。
- **借的是什么**：① 动作是一条**链**，空间上从左到右，时间顺序即空间顺序；② 每个节点都能展开成它的参数与结果，展开不是弹窗而是就地长大；③ 颜色只用来标「已发生 / 正在发生 / 还没发生」，不用来装饰。
- **主角素材**：动作链本身（8 个节点）+ 当前节点的 diff。
- **骨架**：顶部横排管线（8 个节点卡），下方左侧是选中节点的检查器，右侧是「零件箱」（28 件工具），底部输入条。
- **胆量花在哪**：整条链是**一根线**：完成的段是实线，等待确认的那一段断成虚线，批准后电流才接通——状态被画成了物体。
- **form 来自内容的哪里**：Agent 的计划本来就是有顺序的（第 5 步之后还有 3 步），横排管线让「后面会发生什么」先于执行被看见。

## 3 · Linear（现实参照）· Console（指令台）　【完整版 A】

- **逻辑与来源**：现实参照，同媒介桌面应用。Linear 的界面（2026 官网首屏的 app 画面，截图 `refs/linear.png`）：近黑画布、发丝线、13px 字号、键盘优先、信息密度高但不吵。
- **借的是什么**：① 黑不是纯黑：#08090B 画布 + #0D0F12 面板，全靠 1px `rgba(255,255,255,.08)` 分区，几乎不用阴影；② 字号只有三档（11 标签 / 13 正文 / 15 标题），层级靠字重和灰度；③ 强调色只出现在「当前所在」和「可以点」两处；④ 右栏属性区是窄的、静的。
- **主角素材**：动作块——每一步是一块「终端块」，动作名与参数是等宽，结果是人话。
- **骨架**：顶栏 40 + 左图标轨 56 + 中间单列动作流 + 右栏 300 上下文。
- **胆量花在哪**：批准区不做弹窗，直接把 diff 摊在流里，并且**用光标**（▮）指示「现在停在这里」。
- **form 来自内容的哪里**：这个产品本来就是一个「敲一句、它替你做一串」的工具，块状流是它的语法。

## 4 · Zed（现实参照）· Desk（工作台）　【完整版 C】

- **逻辑与来源**：现实参照，同媒介桌面应用。Zed 的编辑窗（2026 官网，截图 `refs/zed.png`）：左文件树、中 Agent 对话、右 diff；浅色、三栏、diff 用绿色/红色行底。
- **借的是什么**：① 三栏的**职责边界**：左边是「有什么」，中间是「在做什么」，右边是「改了什么」；② diff 是文档本身，不是附件——行号、+/-、行底色；③ 浅色界面的层次只靠 1px 线和 4% 的底色差，卡片没有投影。
- **主角素材**：待写入的 diff 文档（中栏），Agent 的步骤退成右栏对话。
- **骨架**：三栏（工具 240 / 文档 1fr / 运行 320）+ 顶部 36px 标题栏。
- **胆量花在哪**：把「批准」放在文档底部，像审稿人签字；拒绝不是按钮，是把草稿退回并留一条批注。
- **form 来自内容的哪里**：Agent 的产出是文件，文件要被审阅；所以界面像编辑器而不像聊天框。

## 5 · Raycast（轮盘 · App #8）· Command Surface　【备选】

- **逻辑与来源**：秒数轮盘抽中「键盘优先命令面板」。看样张 `assets/style-specimens/app/08-command-palette.jpg`：近黑画布、彩色图标块、分组单行列表、右侧键帽、底部操作栏。
- **借的是什么**：① 一切从输入框开始，列表是「建议 / 命令」两组；② 选中行是浅一档的底 + 左侧色条；③ 底部固定操作栏，键盘提示永远在。
- **主角素材**：命令列表本身。
- **骨架**：全屏面板（720×520）浮在暗画布上，背后隐约是上一次运行的残影。
- **胆量花在哪**：把整个工作台做成一个常驻的命令面板，运行详情只在选中后从右侧滑出。
- **form 来自内容的哪里**：43 个动作本来就可以被一句话调起，所以「搜索框」可以当主页。
- **为什么没进完整版**：和 Console 同属深色键盘流，骨架差异不够大；留作备选。

## 6 · 杉浦康平（轮盘 · 东亚 #8）· Mandala　【备选】

- **逻辑与来源**：秒数轮盘抽中「信息曼荼罗」。看样张 `assets/style-specimens/east/08-sugiura-info-mandala.jpg`：暖黑底、金与朱红、同心环、竖排标题、引线注记。
- **借的是什么**：① 同心环 = 时间的层（本次运行 8 步在外环，上下文在里环）；② 朱红只给「当前」一处；③ 引线把环上的点和旁边的说明连起来。
- **主角素材**：径向的运行图。
- **骨架**：环形占 60% 画面，右侧竖排标题 + 三条注记，底部一条时间距离图。
- **胆量花在哪**：整个运行被画成一只盘。
- **form 来自内容的哪里**：8 步有明确的先后与「已发生/未发生」，环能表达「绕一圈就完成」。
- **为什么没进完整版**：用「去掉这个手法，信息更清楚还是更糊」检验——去掉环、改成列表，读者更快知道停在哪一步。它是用力过头的那一张，留作备选。

## 三张完整版：Console / Pipeline / Desk

| | 骨架 | 温度 | 为什么选它 |
|---|---|---|---|
| **A · Console** | 顶栏 + 图标轨 + 单列块流 + 右栏 | 深、密、冷 | 最贴产品语法，也贴用户已记录的偏好（技术感、命令台、深色默认） |
| **B · Pipeline** | 横排链 + 检查器 + 零件箱 | 浅、疏、空间感 | 唯一一个把「计划」画在前面的方向，交互模型最不同 |
| **C · Desk** | 三栏编辑器 + 文档 + diff | 浅、静、文档感 | 把「审阅」变成主界面，最接近「文件要被人签字」的真实工作 |

三张的骨架没有一张是另一张换皮：竖向时间流 / 横向空间链 / 三栏文档。温度也不同（深冷 / 浅疏 / 浅静），外观家族最多两张浅色，且一张是工程纸、一张是编辑器白。

备选三张（Quiet / Command / Mandala）在 `design-demos/thumbs.html` 里有缩略图，看中哪张可以再做完整版。
