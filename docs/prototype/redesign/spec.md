# ToolCove 重设计 · 设计 spec

> 三个方向共用的输入。只写「要说什么」，不写「长什么样」——长相是 `directions.md` 里每张方向卡的事。

## 项目是什么

ToolCove（工具湾）是一个本地优先的桌面工作台：28 件工具、43 个带类型的动作（read / transform / write / database），
既能在工具箱里手点，也能被内置 Agent 规划与调用。写类动作执行前必须出 diff 并等用户点头；策略可设「风险放行 / 每步都问 / 全部放行」。

本轮只重做**工作台这一屏**：一个正在跑、停在第 5 步等确认的运行。

## 受众与场景

- 使用者就是工具的主人：一个每天开它十几次的开发者，常在半屏窗口里用，也常在夜里用。
- 场景：Agent 已经跑完 4 步（只读与转换），第 5 步要覆盖写一个 JSON 文件，弹出 diff。用户需要在几秒内判断「这份 diff 对不对」，然后允许或拒绝。
- 他没说出口的期待：别让我读日志；让我看见**动作的类型和后果**；别在我没点头时动磁盘。

## 核心信息（按重要性）

1. 这是第几步、在等什么、为什么等我（覆盖写，138 KB）。
2. 前四步做了什么（每步：动作名、参数、结果、耗时）。
3. 第 5 步会改成什么（diff，+/- 行）。
4. 允许的边界：这次允许只作用于这一次调用；同一次运行里再写还会问。
5. 后面的计划：06 db.query → 07 data.create → 08 spill.read。
6. 上下文：工作域「订单系统」、3 个代码池、2 条命中的技能；产出两个（待写入的 json、溢出的 spill）。

## 情感基调

精确、克制、不谄媚。技术上的自信，但不做终端 cosplay；不放大数字、不做发光渐变、不卖萌。

## 输出格式与尺寸

- 桌面窗口 **1440×900**（同时保证 1120×760 可用）。
- 每方向 1 个可交互 HTML，单文件、离线可开（系统字体，不引外链）。
- 截图：首屏 1440×900 PNG。
- 内容三版完全一致，只换设计。

## 硬约束

- 中文界面；工具名与动作名取自仓库真实契约（file.inspect / table.parse / table.convert / schema.infer / file.write / db.query / data.create / spill.read）。
- 正文 ≥14px、标签 ≥12px、正文对比度 ≥4.5:1；可点元素 ≥32px（桌面）。
- 交互要真能点：展开单步、允许/拒绝并继续、命令面板可搜、tab 可切。
- 不编造 logo 墙、评价、用户数；运行数据是示例，但必须是自洽的。

## 素材

无照片需求。主角素材是**排版、数据与 diff**——这台机器的动作本身。品牌标记是仓库里的 `public/logo.svg`（蓝渐变圆角方块 + 笑脸），三版都保留其形状，按各自的介质做单色或原色处理。
